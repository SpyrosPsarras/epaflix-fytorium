# Fytorium mobile

React Native (Expo, CNG) app for Android and iOS. It replaces the Kotlin app in `../android/` wave by wave; the plan and its acceptance checks are in `docs/superpowers/specs/2026-11-24-react-native-migration-design.md`. `android/` and `ios/` here are generated by `expo prebuild` and never committed.

## Commands

Run from the repository root on any host with Docker. Every command runs in the digest-pinned image from `docker/Dockerfile`; caches live in `mobile/.cache/`.

```sh
./scripts/mobile install
./scripts/mobile typecheck
./scripts/mobile lint
./scripts/mobile test
./scripts/mobile apk              # debug APK with the JS bundle embedded, plus a fixture-signed copy
./scripts/mobile release-check    # fixture lane: release guards, release APK inspection, fixture signing
./scripts/mobile kotlin-fixture   # Kotlin app at e0edd63 plus e2e/kotlin-fixture/SeedTest.kt, fixture-signed
./scripts/stack up
./scripts/mobile e2e w1
```

`FYTORIUM_ABIS=x86_64` limits native code to the emulator ABI for faster local builds. `FYTORIUM_SERVER_URL` overrides the server; debug builds default to `http://app:3000`, release builds to `https://fytorium.epaflix.com` and refuse anything but HTTPS.

## Variants and Firebase

`FYTORIUM_VARIANT=debug` (default) uses the synthetic `firebase/google-services.synthetic.json` and `firebase/GoogleService-Info.synthetic.plist`. Debug APKs allow cleartext only to `app`, `oidc` and `fake-push`, and carry the exported `DebugPushReceiver` that e2e uses to replay pushes. `FYTORIUM_VARIANT=release` needs `GOOGLE_SERVICES_FILE`; a synthetic config is refused unless `FYTORIUM_FIREBASE_TEST_CONFIG=true`, which only the fixture lane sets.

## Native module

`modules/fytorium-native` holds what Expo modules do not give: the HTTP client with Kotlin's no-retry, no-redirect, 1 s idle pool rules (N1), the restore signal (N3), the push service and refresh worker (N4), first-run cleanup of the Kotlin install (N5), the Obtainium check (N8) and iOS first-run Keychain wipe (N9). Its config plugin keeps backup off, applies the data extraction rules, removes React Native Firebase's own push service and receiver, and embeds the JS bundle in debug builds.

## Release checks

`release/check` refuses a missing Firebase config, a non-HTTPS server URL and an unflagged synthetic config, then builds a release APK and runs `release/inspect`: permissions must equal `release/permissions.txt` (taken from the published Kotlin 1.2.0 APK), the manifest keeps package, SDK 29/35, no backup, extraction rules and no cleartext, the only push handlers are `PushService` and Firebase's default, and neither DEX nor the JS bundle contains a debug hook or test host. The APK is signed with the fixture key, which `release/verify-signer` must refuse against the production fingerprint in `release/fingerprint`. Never publish fixture-signed APKs.

## Test lab

Emulator e2e and native builds run in a disposable lab on the homelab cluster. Create it with `kubectl apply -f mobile/e2e/lab.yaml`; it gets a 25 GiB `truenas-iscsi` volume for Docker data and the checkout at `/src`. Delete it with `kubectl delete namespace fytorium-e2e`, then delete the retained PV. Above 20 GiB used, `scripts/mobile` prunes unused Docker data and the Gradle build cache.

`e2e/device` boots a fresh AVD on the stack's network. Guest DNS goes through a container-local dnsmasq, so `app`, `oidc` and `fake-push` keep their canonical names; readiness gates for boot, package manager, DNS and guest HTTP each have a deadline (`E2E_BOOT_TIMEOUT`, `E2E_PM_TIMEOUT`, `E2E_DNS_TIMEOUT`, `E2E_GUEST_NETWORK_TIMEOUT`, whole seconds). Failure screenshots and window dumps go to `mobile/.cache/artifacts/e2e/`.
