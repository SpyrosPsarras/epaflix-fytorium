# Fytorium mobile

React Native (Expo, CNG) app for Android and iOS. It replaces the Kotlin app in `../android/` wave by wave; the plan and its acceptance checks are in `docs/superpowers/specs/2026-11-24-react-native-migration-design.md`. `android/` and `ios/` here are generated by `expo prebuild` and never committed.

## Commands

Run from the repository root on any host with Docker. Every command runs in the digest-pinned image from `docker/Dockerfile`; caches live in `mobile/.cache/`.

```sh
./scripts/mobile install
./scripts/mobile typecheck
./scripts/mobile lint
./scripts/mobile test
./scripts/mobile apk              # debug APK with the JS bundle embedded, plus a fixture-signed copy
./scripts/mobile release-check    # fixture lane: release guards, release APK inspection, fixture signing
./scripts/mobile kotlin-fixture   # Kotlin app at e0edd63 plus e2e/kotlin-fixture/SeedTest.kt, fixture-signed
./scripts/stack up
./scripts/mobile e2e w1          # scaffold: upgrade cleanup, push gate, launch
./scripts/mobile e2e w2          # session: login, logout, push token lifecycle
./scripts/mobile e2e w3          # shell and data: restore, role change, offline, background refresh
```

`FYTORIUM_ABIS=x86_64` limits native code to the emulator ABI for faster local builds. `FYTORIUM_SERVER_URL` overrides the server; debug builds default to `http://app:3000`, release builds to `https://fytorium.epaflix.com` and refuse anything but HTTPS.

## Variants and Firebase

`FYTORIUM_VARIANT=debug` (default) uses the synthetic `firebase/google-services.synthetic.json` and `firebase/GoogleService-Info.synthetic.plist`. Debug APKs allow cleartext only to `app`, `oidc` and `fake-push`, and carry the exported `DebugPushReceiver` that e2e uses to replay pushes. `FYTORIUM_VARIANT=release` needs `GOOGLE_SERVICES_FILE`; a synthetic config is refused unless `FYTORIUM_FIREBASE_TEST_CONFIG=true`, which only the fixture lane sets.

## Session

`src/session` holds PKCE login, SecureStore credentials and the session controller; `src/api/client.ts` is the API client over the native transport (single-flight refresh, one replay per 401, invalid grant ends the session, logout wipes even offline); `src/push` holds the push token lifecycle from the design. Android opens login in a plain Custom Tab and receives the redirect through `MainActivity`, which keeps redirects that arrive before React is ready, such as after process death during login. iOS uses `ASWebAuthenticationSession` through `expo-web-browser`.

Debug builds replace Firebase tokens with synthetic ones. Launch arguments `pushToken` and `pushDeleteFailures` seed the current token and how many deletions fail; e2e reads the counts from the app's key-value store.

## Shell and data

`src/shell` is the tab shell from the W6 navigation spec: one native stack per tab (Today, Plants, Journal, More; sitters have no Journal), Back at a tab root goes to Today, a tab tap never closes a page, a reselect returns to the root and asks first about a form with changes, a notification tap shows Today at its root, and a tab change waits for a save in flight. Pages a role may not open close when the role changes. Navigation state and drafts come back only when Android recreated the activity for the same member and role.

`src/data` holds the SQLite read cache (`cached_care`, bound to one member and role, as Room's `CachedCare` was), drafts, and the photo cache: only `thumb` and `display` copies on disk, 1 MiB each, 50 MiB in all, wiped with the member. A read that returns after a wipe or a member change is dropped. Offline means no validated network; a failed request or a 5xx on a validated network means Fytorium isn't responding. The 6-hour background read runs through the native WorkManager worker on Android and `expo-background-task` on iOS. W3's root pages and most pushed pages are holding pages that later waves replace.

`e2e/api.sh` logs a synthetic member in through the real app login to seed data with the API.

## Native module

`modules/fytorium-native` holds what Expo modules do not give: the HTTP client with Kotlin's no-retry, no-redirect, 1 s idle pool rules (N1), the restore signal (N3), the push service and refresh worker (N4), first-run cleanup of the Kotlin install (N5), the Obtainium check (N8) and iOS first-run Keychain wipe (N9). Its config plugin adds the Gradle release guard, keeps backup off, applies the data extraction rules, removes React Native Firebase's and Firebase's own push services and receiver, and embeds the JS bundle in debug builds.

## Release checks

`release/check` builds a release APK and runs `release/inspect`, then reruns the warm Gradle release build without `FYTORIUM_VARIANT=release`, without a Firebase config, with an HTTP server URL and with an unflagged synthetic config; the `preReleaseBuild` guard must refuse each. `release/inspect` requires that permissions equal `release/permissions.txt` (taken from the published Kotlin 1.2.0 APK), the manifest keeps package, SDK 29/35, no backup, extraction rules and no cleartext, `PushService` is the only push handler, the cloud-backup and device-transfer rules exclude every domain, the Photo Picker backport is requested, the APK is not debuggable, the embedded app config is the HTTPS release, and neither DEX nor the APK assets contain a debug hook or test host. The APK is signed with the fixture key, which `release/verify-signer` must refuse against the production fingerprint in `release/fingerprint`. Never publish fixture-signed APKs.

## Test lab

Emulator e2e and native builds run in a disposable lab on the homelab cluster. Create it with `kubectl apply -f mobile/e2e/lab.yaml`; it gets a 25 GiB `truenas-iscsi` volume for Docker data and the checkout at `/src`. Delete it with `kubectl delete namespace fytorium-e2e`, then delete the retained PV. `scripts/mobile` prints the volume's use before and after each command. Only in the lab (`FYTORIUM_MOBILE_LAB=1`) and above 20 GiB does it prune unused Docker data and the Gradle build cache; elsewhere Docker is shared and nothing is pruned. W1 peaked at 22 GiB with every image, the Kotlin fixture's Gradle cache and the emulator; the fixture build now drops its Gradle cache and image, which keeps runs near 16 GiB.

`e2e/device` boots a fresh AVD on the stack's network. Guest DNS goes through a container-local dnsmasq, so `app`, `oidc` and `fake-push` keep their canonical names; readiness gates for boot, package manager, DNS and guest HTTP each have a deadline (`E2E_BOOT_TIMEOUT`, `E2E_PM_TIMEOUT`, `E2E_DNS_TIMEOUT`, `E2E_GUEST_NETWORK_TIMEOUT`, whole seconds). Failures leave a screenshot, window dump and logcat in `.scratch/e2e-failures/`; the Maestro launch flow leaves light and dark screenshots in `.scratch/e2e-screenshots/`. On the userdebug emulator image, `su 0` lets the checks read a release build's private files and the Keystore database.
